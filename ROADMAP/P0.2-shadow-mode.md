# P0.2 — Shadow mode: observe-only enforcement + "what would have tripped" report

**Vision:** [VISION.md](../VISION.md) §7 · Phase 0. **Issue:** [#151](https://github.com/Amitcoh1/agentbreaker/issues/151).

Principle §3.3 — **trust is the product; shadow mode first.** Nobody enables enforcement on day one.
*"No enforcement feature ships without its shadow-mode twin."* This is the **adoption unlock**.

## Scope (thinnest slice)
A first-class `shadow=True` flag that evaluates every policy but never trips/degrades — it records what
*would* have happened and reports it.

- `guard(..., shadow=True)` + middleware equivalent: all enforcement paths (budget, hops, ttl,
  velocity, loop, capability, depth, ladder) evaluate and log a would-trip event instead of acting.
- Would-trip event carries the same explainable object as a real trip + a `shadow: true` marker and the
  ledger trail.
- A **"what would have tripped this week" report**: structured JSON + human summary, aggregating
  would-trips by policy/reason. Extend `report/` and expose `breakerbox shadow-report`.

## Acceptance criteria
- [ ] `shadow=True` makes a would-trip run complete to the end, emitting a would-trip record per policy
      that would have fired.
- [ ] Every enforcement reason respects the shadow flag via a **single shared check in the core** (not
      per-caller).
- [ ] `breakerbox shadow-report` renders the aggregated summary (counts by reason, top would-trip runs,
      total $ that would have been prevented) from logged events.
- [ ] ≥3 golden fixtures: (a) budget would-trip in shadow completes + recorded, (b) loop would-trip
      recorded, (c) same policy in enforce mode actually trips (proves shadow ≠ enforce).
- [ ] `.venv/bin/ruff check src tests && .venv/bin/pytest -q` green.

## Out of scope (phase gate)
Org-wide shadow mode + cross-tenant audit trail is Phase 2 (P2.5). Single-node flag + local report only.
