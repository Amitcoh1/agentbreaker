# P3.1 — Gateway/proxy mode

**Issue:** [#161](https://github.com/Amitcoh1/agentbreaker/issues/161)

**Vision:** VISION.md §7 · Phase 3 · **P3.1**. Realizes §6 adapter **Gateway/proxy mode**. Sequenced by open-question §10.1 (where do enterprises require enforcement to live?).

## Scope
Server-side enforcement for the enterprise case where client-side hooks/middleware aren't trusted: a proxy that meters + enforces in front of provider APIs, emitting the same event schema as the in-process adapters.

## Definition of done
- [ ] A proxy path enforces budgets/ladders server-side without the app importing Breakerbox.
- [ ] It emits the unified event schema into the ledger (same as in-process adapters).
- [ ] Degradation is still expressible (the vision's edge: in-workflow degradation a plain proxy can't do — document the boundary).

## Phase gate
Phase 3 (+10 → +18mo). The enterprise/compliance requirement. Depends on the control plane + a validated §10.1 answer from design partners.
