# P0.1 — Harden the LangGraph breaker: degradation ladder v1 + explainable trips

**Vision:** [VISION.md](../VISION.md) §7 · Phase 0. **Issue:** [#150](https://github.com/Amitcoh1/agentbreaker/issues/150).

Principle §3.2 — **degrade before you die.** Tripping is a ladder, not a wall. A run that finishes at
$9 beats a run killed at $50. Principle §6 / arch §6 — trip decisions are **explainable objects, not
booleans**.

## Scope (thinnest slice)
Extend the existing in-process breaker (`guard()` callback + `BreakerboxMiddleware`) with a
**degradation ladder** and **explainable trips**, reusing the core `tripwire`/`ledger`/`meter`.

- Ladder policy: ordered rungs `{threshold, action}` where action ∈ `model_swap` (→ cheaper model) ·
  `tool_narrow` (→ restricted toolset) · `graceful_stop` (return partial results) · `kill` (last rung).
- Default ladder: `0.80 → model_swap + tool_narrow`, `1.00 → graceful_stop`, hard `kill` only last.
- Graceful-stop returns partial results + the trip-explanation object instead of raising.
- Trip decision is an object: `{policy, threshold, counter_value, confidence, ladder_rung, reason,
  override_url}` — serializable to stable JSON. Wrap/extend existing `TripReason`.
- Ladder logic lives in the **pure core** (version-agnostic) so both front-ends share it.

## Acceptance criteria
- [ ] `guard(..., ladder=[...])` and the middleware equivalent accept a ladder policy and apply rungs.
- [ ] At 80% the run swaps to the cheaper model and/or narrows tools; the swap is recorded in the ledger.
- [ ] At 100% the run stops gracefully and returns partial results (no raised exception) with a
      trip-explanation object.
- [ ] Trip-explanation object serializes to stable JSON with all fields above.
- [ ] ≥3 golden fixtures: (a) 80% → model swap, (b) 100% → graceful stop + partial results, (c) an
      error/edge path (no ladder → falls back to current hard-trip). Both front-ends covered.
- [ ] `.venv/bin/ruff check src tests && .venv/bin/pytest -q` green (line limit 100).

## Out of scope (phase gate)
No multi-tenant ledger, no reconciliation, no policy engine — Phase 2. Single-node, in-process only.
